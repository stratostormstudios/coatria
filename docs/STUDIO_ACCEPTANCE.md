# Studio acceptance: what is ready and what remains to prove

Updated 2026-09-20. Exact candidate-head validation is recorded in [draft PR #1](https://github.com/stratostormstudios/coatria/pull/1). The archive-service baseline at `70518a3` passed all four jobs in [CI run 35521578001](https://github.com/stratostormstudios/coatria/actions/runs/35521578001), including real Linux decoder/systemd qualification. This revision adds the selective client-rework cycle and its API, database and browser checks. Public health/OpenAPI observations are recorded in [release status](RELEASE_STATUS.md); deployed source, schema, enabled services and compute still need verification. CI and fixtures are implementation evidence, not a completed client production.

The current path is **brief → references → Higgsfield generation → verified project file → independent review → exact package → authenticated client response**. Scoped agents can coordinate and resume a verified output under explicit finite policy. They do not approve their own media, authorize new provider spending or act as the external client.

## Acceptance matrix

**Fixture** means real application/API/database or browser execution with synthetic identities, requests or provider responses. **Real synthetic media** means the decoder or renderer processed actual original test bytes. These establish technical behavior within their tested environment, not a completed client production.

The generated inspector supports PNG/JPEG/WebP, MP4/MOV and WAV/MP3 within its declared resource and specification bounds. It does not infer missing color tags, use average FPS as proof of constant timing, or turn metadata into creative approval. Client downloads use sequential 4 MiB ranges with live-grant reuse, bounded renewal and whole-file hashing; the fallback without a file-save picker is capped at 128 MiB. Client downloads are not resumable. Native drive indexing remains metadata-only and is separate from the implemented Runpod project-storage transport.

## Shortest complete live validation

1. Record the deployed application commit and migration ledger. Apply the matching restricted grants and qualify the actual storage gateway/volume and isolated archive host before enabling transfer/archiving. Keep test content separate from originals. Follow [storage conformance](PROJECT_STORAGE_CONFORMANCE.md) and [archive qualification](HIGGSFIELD_ARCHIVES.md).
2. Review the AI-production roles, bounded reasoning host and model settings. Involve a suitable independent administrator and a genuine external pilot recipient before scheduling final acceptance.
3. Create one small generated-media deliverable with an achievable specification and authorized reference material. Complete planning and human brief, estimate and production gates. An agent may draft the exact generation request; a human reviews its arguments and credit consent.
4. Observe the completed provider output, approve its exact archive source/destination, and wait for decoded and stored-byte verification. Register that archive manually or enable the finite generated-continuation option and observe its exact claim/register/submit receipts.
5. Have eligible humans inspect and approve the exact media, then independently accept generation and QC work. Prepare the package and accept its separate delivery handoff before inviting the client. Retain the manifest's historical `not_transferred` state.
6. Confirm the external client's account ID through an existing trusted channel. Create the reviewed invitation, share it only through an authorized channel, and have that account download and explicitly respond. Keep access issuance, local checksum success and client acknowledgement separate.
7. Check cancellation/revocation, retained receipts, restart behavior and duplicate prevention. Reconcile actual provider charges and stop resources according to the reviewed session limits.

An owner can prepare the business and draft work alone, but cannot replace independent final QC or impersonate the external recipient. Creative change requests now have a same-project revision workflow in the candidate: exact source-bound drafts, human plan application, fresh tasks, carried approved media, separate renewed generation approvals and new client invitations. See [generated revisions](STUDIO_GENERATED_REVISIONS.md). Technical or commercial scope changes remain unresolved. General VFX/native NAS workflows, autonomous hiring/commerce, cross-company fleet recovery, comprehensive dollar caps and million-user capacity are not established by this candidate.
