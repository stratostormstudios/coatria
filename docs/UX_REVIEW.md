# Coatria product experience review

Reviewed 8 September 2026. Scope: the shipped application, all 15 authenticated destinations, account entry, and the main dialogs and state transitions. This is an expert review with local browser verification and regression tests. It is not a claim that Coatria has completed a user study or that another product's results automatically apply here.

The design direction remains a warm, professional, spatial workplace. The interface should help a person answer three questions quickly: **Where am I? What needs my attention? What can I do next?** The office is the social home; lists, search, and explicit controls make work possible without navigating a 3D scene.

## Production patterns used

These are primary product/design references. Coatria adapts their patterns to its own permissions and available APIs; it does not copy their branding or claim their features are present.

- [Slack keyboard shortcuts](https://slack.com/help/articles/201374536-Slack-keyboard-shortcuts): a predictable keyboard route to navigation. [Slack search](https://slack.com/help/articles/202528808-Search-in-Slack): make search available in the context where work happens.
- [Linear filters](https://linear.app/docs/filters) and [display options](https://linear.app/docs/display-options): separate what is shown from how it is displayed, with ownership and status filters.
- [Carbon data tables](https://carbondesignsystem.com/components/data-table/usage/): place search, filters, and a clear primary action with resource collections. [Carbon empty states](https://carbondesignsystem.com/patterns/empty-states-pattern/): distinguish first use, no results, unavailable data, and permissions; provide a relevant next step.
- [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) and [combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/): accessible names, focus behavior, Escape, and keyboard selection.
- [Notion views, filters, and sorts](https://www.notion.com/help/views-filters-and-sorts): reusable collection controls without mixing content ownership with display choices.
- [Asana task creation](https://help.asana.com/s/article/create-tasks-in-asana) and [approvals](https://help.asana.com/s/article/approvals): distinguish task properties, a submitted result, and a review decision.
- [Gather participants panel](https://support.gather.town/articles/3602925011-participants-panel-overview) and [office desk management](https://support.gather.town/articles/3735354184-add-or-remove-desks-in-your-office): people-first wayfinding with explicit spatial controls.
- [GitHub third-party app installation](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party): separate installation, access scope, and authorization. [Vercel storage documentation](https://vercel.com/docs/storage): describe the actual connected capability and setup state.
- [Microsoft Fluent search box guidance](https://fluent2.microsoft.design/components/web/react/core/searchbox/usage/): meaningful search labels and contextual results.

## Follow-up work that needs product or backend development

1. **Arrival and activation:** measure the first successful invitation, first teammate interaction, first submitted result, and first accepted contribution. Add a small resumable owner checklist if observed drop-off supports it. Avoid an obligatory product tour.
2. **Deep links and shared views:** stable links to a task, room, opening, or application; saved filters; preserve view state in URLs. This pass restores page history, not resource-level routing.
3. **Notifications and message scale:** a durable unread model, mentions, search across history, pagination, and notification controls. Current polling and workspace payload bounds need architectural work before large companies.
4. **Calls:** production TURN/SFU configuration, pre-call device selection, reliable network diagnostics, and an explicit policy for calls while navigating. The current six-person direct-call implementation is not an auditorium service.
5. **Editing durability:** server revision checks for layouts and other shared editors. A client warning about a polled update reduces accidental overwrites but cannot provide atomic conflict prevention. Local drafts across reloads need an explicit personal-data retention policy.
6. **Hiring and infrastructure:** payment/contract workflows, reputation explanations and appeals, managed provisioning, secure media transfer/access, and connector installation UX. An accepted application is not employment, payment, or automatic company access; a file index is not shared media storage.
7. **Account and accessibility:** recovery/verification delivery, SSO where needed, end-to-end assistive-technology review, localization and long-text testing. Larger type and semantic fixes are improvements, not a WCAG certification.

## Pilot usability study

Recruit 5–8 people across owner/admin, employee, contractor, and agent-operator roles for the next qualitative round. Ask them to create/join a workplace, find a colleague, enter the right room, submit/review work, connect an agent, locate a storage file, apply for a role, and change a character. Record completion, wrong turns, assistance, and task time. Ask what they believe the company can see versus what stays private. Use observed failures to choose the next iteration; do not treat this sample as a population estimate.

Success measures should emphasize useful outcomes: completed onboarding, successful collaboration, accepted work, connection setup success, recoverable errors, and accessibility. Token volume is resource consumption, not a performance score.
