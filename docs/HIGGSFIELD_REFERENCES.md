# Managed project references

This implementation connects exact project-storage image versions to company Higgsfield generations. It is a prepared-image workflow: PNG, JPEG or WebP, at most 10 MiB, 4096 pixels per dimension and 16 million pixels. These are Coatria policy limits, not claims about provider limits.

The original file may be linked separately for provenance. It is never substituted for the prepared image. Inspection fully decodes the prepared image and checks its hash; it does not resize, re-encode or remove embedded metadata. The approval explicitly covers all unchanged bytes. Automatic proxy preparation remains separate unfinished work.

## Authority and execution

1. A member or assigned, leased agent proposes an exact version, hash, byte count, role and purpose against a current project and reference/generation task.
2. A qualified worker reads that version into private bounded scratch storage, verifies all bytes, and records full image inspection. No Higgsfield upload occurs at this stage.
3. An administrator reviews the exact image and grants finite sharing permission. Inspection and archive approval do not confer this permission. Agents have no approve/revoke tools.
4. The worker rechecks source, storage, project, task, sponsor, provider connection and approval. A server broker keeps company OAuth private and records a durable intent before allocating an upload, sending bytes or confirming it.
5. Each provider-changing phase is once-only. Lost responses, lease loss after an intent, or failed receipt commits retain an uncertain outcome. They are never automatically replayed.
6. Generation proposals select internal `referenceIds`. The server resolves confirmed approved roles/media IDs, stores the immutable reference snapshot in the generation hash, and revalidates it before cost preflight and paid dispatch. Raw media arguments cannot be combined with this managed path.

Revocation stops future work at the next authority check. It cannot undo bytes already disclosed. Provider confirmation proves the supported receipt was observed, not that generated media, creative review or client delivery is complete.

Inspection, approval and transfer pin both the exact project revision and its immutable semantic snapshot. There is one consumption-only exception: a confirmed reference from an accepted, unchanged reference task may remain usable by its direct generation successor on the same shot after a bookkeeping revision change. The complete normalized project row must still match, excluding only `revision` and `updated_at`; brief, specification, gates, status, client and all other fields remain pinned. The task content, role, shot, current production round, source, storage, provider connection, sponsors and finite approval are revalidated. The generation request separately pins its current project revision.

Ordinary markerless agent proposals still require the original run to remain live through inspection. A separate administrator-selected `prepared_image_v1` dispatch creates immutable, exact inspection authority: at most one hour from the exact proposal, three inspection claims and eight proposals for the work content. It may inspect after factual `tasks_submit` and successful run completion only when their committed receipts prove the original task reservation and unchanged content. Independent acceptance may then move that exact submission from review to done. Failed, cancelled, retried or manually forged terminal runs do not qualify. Current agent, installation, requester, sponsor, task, storage, project and provider epochs remain enforced. Inspection does not confer sharing consent. Finite human approval after inspection adopts the transfer, which may outlive the original run under all current authority checks.

## Interfaces

Session endpoints are under `/api/companies/{companyId}/higgsfield/references`: paged list/proposal, `/candidates`, exact `/{referenceId}`, and administrator `/{referenceId}/approve` and `/revoke`.

Leased agents use `higgsfield_reference_propose`, `higgsfield_reference_candidates_list`, `higgsfield_references_list` and `higgsfield_reference_get`. Current storage, studio and creative capabilities are checked. Session and agent endpoints never expose OAuth, upload locators, worker leases, arbitrary provider calls or original file bytes.

Prepared-dispatch proposals and reference metadata require `creative.read`, `studio.read`, `studio.write`, `tasks.write` and `storage.read` on the current agent and run, together with the relevant task reservation. Existing reviewed AI-production ingest staffing has these grants; dispatch does not add or alter them. Markerless legacy proposals and generation consumption additionally require `creative.write`. Metadata reads may inspect references from another role under the reader's own current project task; proposal and generation-use authority remain bound to the exact relevant task.

The server-owned generation profiles expose `higgsfield_references_list` after the assigned task is reserved. Its paged metadata lets the harness discover confirmed internal IDs and pass them as generation `referenceIds`; the server still validates finite approval, exact task/dependency and provenance. The narrower coordinator-generation child replaces its two storage-browsing tools with this project-bound discovery tool and remains within its existing catalog byte limit. Ordinary generation specialists retain storage browsing for archive destinations. Neither profile gains reference approval or upload powers.

In Production work, an administrator can choose **Select prepared images** beside **Queue specialist** on a ready generated-project reference task. The corresponding normal API is `POST /api/companies/{companyId}/studio/projects/{projectId}/dispatch` with the existing stable `clientId`, current `revision`, exact `workItemId` and optional `preparationProfile: "prepared_image_v1"`. Omission preserves the existing planning profile and request hash. The server inserts a new immutable marker in the fresh queued-run transaction; prompt text, role names and caller-supplied agent tool arguments cannot opt in.

The prepared profile exposes seven tools: exact `studio_get`, `tasks_claim`, `tasks_submit`, project-bound reference candidate discovery, reference list/proposal, and safe company connection metadata. The same work/project rules run before cached receipts are replayed. The specialist reports proposal IDs and pending inspection/rights/sharing in its submission, then completes its run; it must not poll indefinitely or claim that unchanged bytes were sanitized. Coordinator policies preserve the original reference-planning profile when the new option is omitted. An owner or administrator can explicitly enable **Allow prepared image reference selection**, or save `referencePreparationProfile: "prepared_image_v1"` through `PUT /api/companies/{companyId}/studio/projects/{projectId}/coordination`. Only matching v2 reference work assigned to a separate permitted specialist gets the same seven-tool profile; the policy requires that specialist’s five existing grants and adds none. The server inserts the exact parent/child/policy marker atomically with its single lifetime run reservation. Prompt text and agent parameters cannot select the profile. The original coordinator request must be sponsored by the current policy approver.

Coordinated proposals also pin the exact policy revision and expiry, coordinator identity/credential/installation, approving administrator and sponsors, and parent request attempt. Later inspection requires that policy to remain active and unchanged; a successfully completed child does not bypass pause, expiry, revision, revocation, or a failed/cancelled/unreceipted parent. A parent may remain live or have a committed successful completion receipt. An exhausted run allowance does not cancel work already counted. Inspection expires at the earliest of one hour, specialist credential expiry and policy expiry. Factual task submission and the original specialist’s successful completion receipts are still required for post-run inspection. Automatic image transformation remains unfinished work. Generation still waits for inspected, separately approved and confirmed references.

## Activation status

### Dedicated reference service

The separate worker protocol is `POST /api/internal/reference-services/{serviceId}/{operation}` with an `rfs_` bearer credential. Browser cookies, origins, query credentials and arbitrary URLs are rejected. Each JSON request has a UUID `requestId`; reference operations additionally supply only `referenceId`, `leaseId` and `requestHash`. The server resolves the enrolled company/project and immutable leased image. It does not trust a caller-supplied company, storage key, provider model or qualification flag.

| Operation | Result and boundary |
| --- | --- |
| `readiness`, `claim`, `authorize` | Current finite qualification, one active lease per service, and current exact reference authority |
| `read-proxy` | One exact ETag-bound streaming read per lease, at most 10 MiB; private bytes and storage credentials are never persisted in the request receipt |
| `inspection` | Exact image descriptor and enrolled decoder-profile hash; this is not external sharing consent |
| `allocate`, `upload-capability`, `begin-put`, `complete-put`, `confirm` | Existing once-only phase fences; only the dedicated runner can receive the approved private upload capability |
| `fail` | A bounded cleanup-only receipt, including up to ten minutes after instance expiry; no renewed read or provider authority |

The broker uses an explicitly injected pool authenticated as `coatria_higgsfield_reference_broker_v1`. Its provisioning script refuses an existing role, establishes exact grants, and validates a separate LOGIN. The ordinary runtime, archive and gateway identities do not receive these permissions. Database triggers protect monotonic bounded inspection claims, completed call receipts and read-only lock columns. A failed or lost mutating RPC remains started/uncertain and is not repeated. Dedicated service credentials belong outside model context; the secret scanner recognizes their prefix.

The normal application can list services through `GET /api/companies/{companyId}/higgsfield/reference-services` and stop an exact revision through `POST /api/companies/{companyId}/higgsfield/reference-services/{serviceId}/revoke` with `{revision}`. Only current administrators can use these endpoints. Stop records retain the acting administrator. The runtime cannot enroll, qualify, extend, restart or un-revoke a service. Human approval readiness also requires the dedicated database pool's real privilege preflight, not merely a configured URL.

The runner source is `scripts/hosting/run-reference-worker.mts`. It requires a verified immutable host installation and a reference-specific v2 receipt binding the configuration, runtime artifacts, current boot, UID/GID, company/projects, decoder profiles, service units and expiry. Its actual cgroup comes from the current loaded systemd unit, not a caller-selected path. It loads the actual isolated Linux decoder; no production fake inspector or inherited application credentials are accepted. Its JSON client is bounded, rejects redirects, and never retries mutating requests. A lost claim stops the runner instead of claiming another image.

Cancellation waits for the original local operations and inspector to settle before closing handles or removing scratch. Cleanup has a finite maximum of ten seconds; a timeout, failed cancellation, failed close or failed removal permanently stops new claims from that worker instance. Completed remote receipts are retained, and prior provider intent remains uncertain rather than being retried. Host control-group termination is still required for unresponsive native processes; a timed-out JavaScript promise is not evidence that a process was killed.

Startup and preflight also reject any leftover scratch entry before loading the sandbox or making a service request. Restarting the process cannot silently bypass retained-file cleanup, and the check never deletes those files.

The offline trusted-service builder accepts the `reference` and `reference-qualification` entries and pins their standalone runtimes, reviewed source/tree, compiler and all dependency inputs. The reference-only host packager adds the native closure and fixtures without installing runtime Node packages. Its installer creates disabled units and no credentials. The compiled qualifier and root receipt acceptance operate independently of application enrollment. This does not permit the archive/gateway bootstrap to install or start a reference service, and a built bundle remains unqualified.

The separate compiled `reference-registrar` now enrolls a reviewed scope under a dedicated metadata/insert-only database role. It checks current accepted host evidence, project approvals and revisions, administrator sponsors, provider catalog and storage bindings; it saves the service, project bindings and immutable enrollment identity atomically. Root-only pending files retain one credential through crashes and uncertain commits. Fresh same-lock reconciliation must confirm the exact active tuple before publishing it to the worker. The application cannot register, extend or restart a service, and the registrar never starts one.

This is an implemented service interface and deployment path, not a completed production activation. Actual finite enrollment, provider/storage compatibility and actual-host end-to-end qualification are still required. Operator tables have no public registration endpoint, and no production service has been enrolled by this change. The API fixture uses synthetic enrollment and inspection evidence; the independent LOGIN, concurrency and commit-reconciliation suite is separately gated on real PostgreSQL. See `HIGGSFIELD_REFERENCE_DEPLOYMENT.md` for artifact identities, installation, acceptance and enrollment boundaries.

The [reference deployment contract](HIGGSFIELD_REFERENCE_DEPLOYMENT.md) defines the artifact hashes, separate qualification/acceptance/enrollment steps and required activation evidence.

Only prepared images use the bounded streaming broker read. Heavy originals and ordinary project downloads remain on the separate storage gateway. Vercel documents a 4.5 MB buffered response limit and streaming as the alternative; the exact deployed binary-stream path must still be exercised before activation ([Vercel guidance](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions)).

The reference worker is disabled by default. This change does not deploy a worker, create a host, grant a database role, enable a credential, migrate production or spend provider credits. Activation requires qualification of the actual company catalog and receipt shape, exact upload hosts, bounded storage reader, isolated decoder and finite company/project runtime. A matching ChatGPT plugin schema is supporting information, not evidence of the company's MCP contract.

The first adapter accepts `media_upload` with a single generated filename, content type and `method: upload_url`; it accepts one structured PUT allocation and one structured image confirmation with status `confirmed`. Unknown schemas and receipt shapes fail closed and need adapter review. Synthetic fixtures prove the local state machine, not live compatibility.

Managed generation arguments must satisfy the entire supported tool schema, including required fields, scalar and array bounds, and media item constraints. The original literal-model branch remains supported. A generic model string instead requires a current company model contract from the official `models_list` or `models_get` read. The **Available models** button performs that existing authenticated read; callers cannot supply a trusted descriptor in a proposal. The observed company `generate_image` schema and selected model constraints were inspected on 2026-09-28; the regression fixture keeps only contract fields, without credentials or account data. This observation does not qualify uploads or prove successful generation.

The model cache expires after 15 minutes and binds the company, connection ID/revision and complete tool-catalog hash. Unsupported new observations retire old support for that model. Managed proposals include the immutable model contract in their request hash. Cost preflight and paid dispatch revalidate it before contacting the provider. Refreshing unchanged metadata preserves a proposal; changed semantics require new review. Agent `higgsfield_connection_get` returns a bounded cached model list; its optional `modelId` returns the exact safe contract. An empty/stale cache tells the caller to refresh through the administrator's existing read endpoint; automatic coordinator refresh is not yet implemented.

The adapter supports one image-media input collection and the advertised `image`, `start_image` and `end_image` roles. Coatria's eight-reference bound still applies, as do smaller model limits. Reviewed extra scalar parameters are `quality`, `resolution`, `genre` and `generate_audio`; unknown media aliases, nested inputs, external locators and unreviewed model-specific values are not forwarded. A descriptor can fill only an explicitly advertised `additionalProperties: {}` extension. It cannot open a closed schema or replace existing parameter, union or required-field assertions. Both generation arguments and the forced `get_cost: true` estimate copy satisfy that full envelope. Unknown assertions, schema references and provider regex patterns fail closed.

The broader goal still needs automatic proxy preparation and a live reference → generation → archive → independent QC → delivery → client acceptance verification.
