# Runpod runtime deadlines and spending limits

Coatria reserves a bounded CPU allowance before admitting a managed host or trusted service. The reservation includes five minutes beyond the planned lifetime. This is an admission control, not an account-level billing cap: the public plan intentionally reports `billingCapGuaranteed: false`. Storage and inference require separate allowances.

The worker stops its own work at expiry. Vercel cron reconciles provider state every minute and explicitly requests a stop. Managed-host batches prioritize expired or stop-requested provisions over ordinary polls, then select the least recently reconciled provision (unseen first, UUID breaks ties). Active leases remain excluded. This prevents healthy fleet polling from burying shutdowns and rotates failed stop attempts within their priority class. It does not guarantee shutdown within five minutes during an application, database, credential, scheduler, or provider outage.

Runpod's former `--stop-after` and `--terminate-after` flags are not a provider deadline control. [Runpod CLI PR #330](https://github.com/runpod/runpodctl/pull/330), merged August 27, 2026 and released in v2.12.0, removed them because accepted GraphQL timestamps did not stop billing; CPU creation silently dropped them. The fields were write-only, with no readable deadline. [Restoration PR #331](https://github.com/runpod/runpodctl/pull/331) was still a draft when checked on September 22, 2026; it explicitly depends on backend enforcement and rejects CPU scheduling. Do not restore these flags or infer scheduling support from older examples.

The current [REST v2 create contract](https://docs.runpod.io/api-reference-v2/pods/create-a-pod) has no scheduled-stop field. Coatria instead uses [the explicit state-transition contract](https://docs.runpod.io/api-reference-v2/pods/trigger-a-pod-state-transition): `POST /v2/pods/{id}/action` with `{"action":"stop"}`. A subsequent authoritative provider read must confirm `EXITED` or `TERMINATED`; submitting the action or ending the worker process is not billing verification. Retained volumes remain separately billable. Keep reservations until actual usage is reconciled, and preserve uncertain resources for explicit reconciliation rather than assuming they stopped or recreating them.

An independently hosted watchdog would reduce dependence on Coatria's own scheduler, but is not implemented by this batch-order change and would not itself establish a guaranteed provider spending cap.
